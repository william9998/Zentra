把使用者的產品想法整理後寫進 Notion「產品規劃」。

使用者的主題或想法：$ARGUMENTS

## 先讀
- `.claude/notion-workspace.md`：位置、資料庫快取、共用規則（一定要照著做，特別是**不使用任何表情符號**）。
- 產品規劃頁面：https://app.notion.com/p/41c2dbee508080be8cacca800612467c

## 步驟
1. fetch 產品規劃頁面，確認分類（inline 資料庫）有沒有變，對照快取表。
2. 選分類：

   | 內容 | 分類 |
   |---|---|
   | 功能、能力、需求、路線圖 | 產品規格 |
   | 某人說的話、遇到的痛點、使用情境 | 使用者回饋 |
   | 其他產品怎麼做、比較 | 競品分析 |
   | 定位、說法、管道、素材 | 行銷 |

   - 一個想法可能拆成多列寫到不同分類（例：「一個新功能」寫產品規格，「它要解決的痛點」寫使用者回饋），用 mention 互相連結。
   - 都不適合（例：定價、合作夥伴）→ 照 `.claude/notion-workspace.md`〈分類模型〉提出新分類，等使用者同意再建。分不出來先問使用者。
   - 競品分析需要外部資訊時可以上網查，內文附來源連結；查不到的標「未確認」。
3. 查有沒有同主題的列：有就補充，沒有才新增。
4. 需要知道產品現在做得到什麼時，看 `README.md`、`CLAUDE.md` 開頭與 `specs/*.md`（`agent.md` 是開發者怎麼寫與發布 Agent、`mcp.md` 是 MCP 接口、`api.md` 是 REST），在內文標明「已實作」或「規劃中」。
5. 內文建議段落（依資料庫性質取捨，參考既有列的寫法優先）：
   - **痛點／使用情境**：誰（Agent 開發者、呼叫 API／MCP 的使用者、平台管理者）、在什麼情況、遇到什麼問題
   - **想法／解法**
   - **跟現有功能的關係**：表格「已經有的能力 → 用在這裡」
   - **會不會碰到平台底線**：使用者程式碼只在容器跑、容器沒有長期憑證、版本以 digest 識別（見 `CLAUDE.md`〈底線〉）；會碰到就寫出來
   - **優先順序與理由**、**風險／未決問題**
   - `## 下一步／怎麼驗證`
6. 使用者說的照實記錄；你的補充放在標題為「Claude 建議」的段落。
7. 回報：寫到哪個資料庫、哪一列（新增或更新）、連結。
